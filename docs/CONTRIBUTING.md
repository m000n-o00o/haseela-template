# طريقة العمل للفريق

يملك صاحب الموقع (المشرف) المستودع، ويوزّع الفصول على الفريق، ويراجع العمل ويرفعه. وللمشاركة طريقتان تؤديان إلى النتيجة نفسها.

## الطريقة الأولى: دون GitHub (بملف مضغوط)
1. **مرة واحدة:** يُؤخذ من المشرف الملف `haseela-starter.zip`، وفيه الأدوات والقواعد دون محتوى الفصول، وتُضاف مهارة «haseela-chapter» إلى الحساب في Claude. ويُعِدّ المشرف هذا الملف بضغط المستودع دون المجلدات `work/<المادة>/` و`content/<المادة>/chNN/`.
2. **محادثة جديدة لكل مجموعة فصول:** تُرفق فيها:
   - الملف `haseela-starter.zip`.
   - شرائح الفصول، وتُجمع في ملف مضغوط إذا كثرت.
   - نماذج الاختبارات القصيرة والنصفية المحلولة إن وُجدت.
3. **الرسالة الأولى:** تُكتب مثلًا: «جهّز الفصول من 1 إلى 3 من مادة DM باستخدام مهارة حصيلة، دون GitHub».
4. **الملف الناتج:** يُنجز Claude العمل كاملًا ويُخرج ملفًا مثل `haseela-DM-1-2-3.zip`، لا يحوي إلا عمل تلك المادة.
5. **الإرسال:** يُرسَل الملف إلى المشرف، فيفكّه داخل المستودع ويرفعه. ولكل مادة ملف فهرس خاص بها، فلا يطغى عمل أحد على عمل غيره.

## الطريقة الثانية: باستخدام GitHub

### مرة واحدة
1. **الوصول إلى المستودع:** يضيف المشرف أعضاء الفريق متعاونين (Collaborators)، ثم ينسخ كل عضو المستودع إلى جهازه عبر GitHub Desktop بخيار Clone.
2. **مهارة حصيلة:** تُضاف مهارة «haseela-chapter» إلى الحساب في Claude.
3. **أدوات البناء:** للبناء على الجهاز، يُشغَّل `npm install` ثم `npx playwright install chromium` داخل المجلد `tools`. ويلزم أيضًا Python مع الحزم `pyyaml` و`Pillow` و`playwright`، وأدوات `poppler`، وLibreOffice للشرائح بصيغة pptx.

### لكل مجموعة فصول
1. **التوزيع:** يحدد المشرف لكل عضو المادة والفصول، حتى لا يعمل اثنان على الفصل نفسه.
2. **الفرع:** يُنشأ فرع جديد في GitHub Desktop باسم مثل `dm-ch1-3`.
3. **المحادثة:** تُفتح محادثة جديدة في Claude لكل مادة، ويُرفق فيها المستودع وشرائح الفصول ونماذج الاختبارات المحلولة إن وُجدت، ثم يُكتب: «جهّز الفصول من 1 إلى 3 من مادة DM باستخدام مهارة حصيلة».
4. **الأوامر:** يشغّلها Claude بهذا الترتيب:
   - `python3 tools/prep_slides.py DM 1 <ملف الشرائح>` لكل فصل.
   - كتابة ملفات `work/DM/`.
   - `COURSE=DM node tools/build.js 1,2,3`
   - `python3 tools/check.py DM 1 2 3`، ويجب أن تكون نتيجته OK.
   - `python3 tools/site_content.py DM`، لتحديث `content/DM/chapters.json`.
5. **المراجعة الذاتية:** تُفتح صفحة «مراجعة الترجمة» من `.build/out/DM/chNN/` لمراجعة الترجمة، ويُتحقق من أن الملخص صفحتان.
6. **الرفع:** يُنفَّذ Commit ثم Push إلى الفرع، ثم يُفتح طلب دمج (Pull Request).
7. **الدمج:** يراجع المشرف الطلب ويدمجه، ولا يدمج أحد غيره في الفرع `main`.

## قبل فتح طلب الدمج
- نتيجة `tools/check.py` هي OK.
- لكل سؤال مصدر، وأسئلة الاختبارات القصيرة والنصفية مطابقة لنماذجها.
- الملخص صفحتان، ولا يتضمن شيئًا من الأجزاء المحذوفة من المنهج.
- العرض التفاعلي يعمل في الوضعين الفاتح والداكن.
- لا تعديل خارج `work/<المادة>/` و`content/<المادة>/` إلا بموافقة المشرف.
