# طريقة العمل للفريق

صاحب أو صاحبة الموقع (المشرف) يملك الريبو، ويوزّع الشباتر، ويراجع الشغل ويرفعه. وفيه طريقتين للمشاركة، والاثنتين يطلعون نفس النتيجة.

## الطريقة الأولى: بدون GitHub (ملف zip)
1. **مرة وحدة:** خذوا من المشرف ملف `haseela-starter.zip` (الأدوات والقواعد بدون محتوى الشباتر)، وأضيفوا مهارة «haseela-chapter» لحسابكم في Claude. والمشرف يسوي هذا الملف من الريبو بأي أداة ضغط، بدون مجلدات `work/<المادة>/` و`content/<المادة>/chNN/`.
2. **محادثة جديدة لكل دفعة شباتر:** أرفقوا فيها:
   - `haseela-starter.zip`
   - سلايدات الشباتر، وإذا كثيرة اجمعوها في ملف zip.
   - نماذج الكويزات والميد المحلولة إن وُجدت.
3. **أول رسالة:** اكتبوا مثلًا: «جهّز الشباتر 1 إلى 3 من مادة DM على مهارة حصيلة، بدون GitHub».
4. **الملف الناتج:** Claude يسوي كل شي ويعطيكم ملف مثل `haseela-DM-1-2-3.zip`، وفيه شغل مادتكم فقط.
5. **الإرسال:** أرسلوه للمشرف، وهو يفكّه داخل الريبو ويرفعه. وكل مادة لها ملف فهرس خاص فيها، فما يمسح شغل أحد شغل الثاني.

## الطريقة الثانية: مع GitHub

### مرة واحدة
1. **الوصول للريبو:** المشرف يضيفكم Collaborators في الريبو، وبعدها تنسخونه بـ GitHub Desktop (Clone).
2. **مهارة حصيلة:** أضيفوا مهارة «haseela-chapter» لحسابكم في Claude.
3. **أدوات البناء:** إذا بتبنون على أجهزتكم، شغّلوا `npm install` ثم `npx playwright install chromium` داخل مجلد `tools`. وتحتاجون Python مع `pyyaml` و`Pillow` و`playwright`، وأدوات `poppler`، وLibreOffice لملفات pptx.

### لكل دفعة شباتر
1. **التوزيع:** المشرف يحدد لكل شخص المادة والشباتر، عشان ما يشتغل اثنين على نفس الشابتر.
2. **الفرع:** سووا فرعًا جديدًا في GitHub Desktop باسم مثل `dm-ch1-3`.
3. **المحادثة:** افتحوا محادثة جديدة في Claude لكل مادة، وأعطوها الريبو وسلايدات الشباتر ونماذج الكويزات المحلولة إن وُجدت، واكتبوا: «جهّز الشباتر 1 إلى 3 من مادة DM على مهارة حصيلة».
4. **الأوامر:** Claude يشغّلها بهالترتيب:
   - `python3 tools/prep_slides.py DM 1 <ملف السلايدات>` لكل شابتر.
   - كتابة ملفات `work/DM/`.
   - `COURSE=DM node tools/build.js 1,2,3`
   - `python3 tools/check.py DM 1 2 3`، ولازم يطلع OK.
   - `python3 tools/site_content.py DM` (يحدّث `content/DM/chapters.json`)
5. **المراجعة الذاتية:** افتحوا صفحة «مراجعة الترجمة» من `.build/out/DM/chNN/` وراجعوا الترجمة، وتأكدوا إن الملخص صفحتين.
6. **الرفع:** سووا Commit وPush للفرع، وبعدها افتحوا Pull Request.
7. **الدمج:** المشرف يراجع ويدمج، ولا أحد غيره يدمج في `main`.

## قبل فتح Pull Request
- `tools/check.py` يطلع OK.
- كل الأسئلة لها مصدر، وأسئلة الكويز والميد مطابقة لنماذجها.
- الملخص صفحتان، وما فيه نقاط من المحذوف.
- العرض التفاعلي يشتغل في الوضعين الفاتح والداكن.
- ما فيه أي تعديل خارج `work/<المادة>/` و`content/<المادة>/` إلا بموافقة المشرف.
